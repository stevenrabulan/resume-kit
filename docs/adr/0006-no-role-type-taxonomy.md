# No role-type taxonomy

The private original classified every posting into one of three role types, which
then selected a cover letter format. We removed it: the master resume already
holds every fact and the posting already determines which facts surface, so the
classification step earned nothing, and the three types were specific to one
person's career.

## Considered options

Keeping the taxonomy but making it user-defined during setup. Rejected as
configuration burden for something an agent can read off the posting directly.

`skills/cover-letter-builder.md` instead describes format *dimensions*
(outcome-led, craft-led, mission-led) that the agent chooses between per posting.
Do not reintroduce a fixed taxonomy.
